## 1. 一句话定位

Orbit 是一个云端 Agent 平台：用户把一件事交给 Agent，Agent 在该任务自己的云端工作空间里执行，遇到有风险的操作先停下来请用户批准，最后交出产物；复杂的事可以由主 Agent 在同一个任务里用 @ 拉入多个子 Agent 一起完成。网页端是 orbit-web，品牌名 MindBuddy。

仓库写明的部分：orbit-control 定义了三种产品形态，即单 Agent（`solo` 房间，W1）、多 Agent（`collab` 房间，P0）和 Cloud Agent（克隆仓库、跑一轮、提 PR，后续）；orbit-runtime 的系统提示是 "Orbit business agent"。产品定义上不再区分两种房间：一个任务就是一个房间，单 Agent 和多 Agent 都在同一个任务里进行（见「术语」）。

## 5. P0 成功标准

1. 用户用真模型完成一次含工具调用和审批的任务：建任务 → 看到工具调用实时出现（2 秒内，不刷新）→ 批准 → 拿到最终回复。
2. 用户点「拒绝」后，该工具调用确实没有执行，后端日志和文件系统都能验证；撤销"总是允许"后，下一次同类调用重新询问。
3. 追问卡里的回答（含"其他…"自由文本）回到对话中，Agent 下一轮能引用；待办和子 Agent 工具要么显示数据，要么显示明确的空状态。
4. 任务台和侧栏不出现能点但没反应、或只弹"暂未开启"的入口；P0 期间 UI-only 全页面保持可见，统一置灰并标「未接入」。
5. 界面上始终能分辨当前是假模型还是真模型。
6. 未登录的人访问任何任务、产物或事件接口，一律被拒绝（返回 401，且在查任何数据之前拦截）。

## 7. 产品定义与技术基线

Orbit 与 MindAI 门户是同一条产品线，项目沿用 MindAI 定义（见 `agent-platform-ix-spec.md`），其余概念以本文「术语」为准（2026-09-26 确认）：**项目** = 资源与数据边界，并承载成员、指令、连接器、专家、技能、项目资料；**任务组**（`taskGroup`，可选）= 项目下某一类任务的集合；**任务** = 一个房间 = 一个对话 + 一个工作空间，多 Agent 协作也在任务内完成。此前「空间 = Agent 协作容器」的定义作废；"工作空间"指任务自己的云端文件区，"团队空间"指资料库里的共享区域，两者都不是协作容器。

技术基线已确认：AgentScope（orbit-runtime agent framework）与 Vite（orbit-web build tool）。`ARCHITECTURE.md` 和 `docs/ia-w0.md` 已过时，Celestial 正在更新架构文档。

## 8. 2026-09-26 产品决策

- **审批规则（P0）**：用户拒绝后工具不执行、任务不关闭；Agent 收到「用户拒绝了」后继续，可换办法或追问。卡片变为「已拒绝」且不可再点；要整体停掉用「停止」。
- 「总是允许」默认只记住本次完全相同的参数；「该工具任意参数都允许」放二级选项且需明确选择，危险（destructive）工具不提供「总是允许」。
- 模型一次发起多个需审批的调用时，每个调用一张卡、各自单独决定；P0 不做「全部允许」。子 Agent 的审批和追问出现在同一个任务台，卡片标明所属子 Agent。
- **MCP 工具风险等级（P1）**：由管理员在连接器配置（开发态）中标注；普通用户不能修改或降级。未标注的 MCP 工具不禁用，按最高风险处理（每次询问且无「总是允许」）。
- MCP 服务端自带的只读/删除提示仅作预填建议，须管理员确认；内置工具未声明风险等级则注册失败，由 CI 拦截。
- **SOP 标准化任务（P1）**：用户或管理员可保存带版本号的固定流程模板；每步声明输出格式、可用工具和预算限制，步骤间可插入审批或校验。技术上由 Temporal 推进步骤、每步调用一次 AgentScope，不依赖 P0。

## 9. 企业内部定位与 C 端裁剪（2026-09-26 用户/产品负责人确认）

原则：Orbit 只在企业内部使用。「个人自用、对外社交」的功能删掉；由公司统一配置的放到管理员/控制面；任务台只留完成工作所需。

- **删除（不做灰显）**：我的邮箱、灵感、网盘与「我的文件」（企业文件只放在任务工作空间，以及资料库的团队空间/我的文档）、发布与发布链接、检查更新（桌面客户端概念）、意见反馈假提交、对外外链（见下条）。
- **对外外链**：P0 和 P1 都不做对外分享（企业内部使用）。同事查看同一任务以后走任务成员和项目权限。
- **保留并灰显「未接入」**：项目（含任务组）、专家、技能、连接器、定时任务、资料库、助理、记忆；助理和记忆以后需提供管理员可控的开关。
- **设置拆分**：个人设置只留个人资料、语言、主题；成员、模型与密钥、连接器授权、用量与额度归管理员，放在控制面管理台，P0 不出现在个人设置；前端不得出现模型密钥输入框。
- **技能导入（P1）**：由管理员在开发者模式挑选导入到本租户目录，页面标明来源（如 SkillHub）。
  - 只收写明宽松许可证（MIT、MIT-0、Apache 等）的技能；包内 LICENSE 与 frontmatter 不一致，或写专有、未写明许可证的，一律拒绝。
  - 导入时记录来源、版本、整包 sha256；市场出新版本不自动覆盖，须管理员重新审核；拒绝重名；技能名字和描述有长度上限，并纳入审核。
  - 技能内容按不可信处理，不能放宽任务权限，技能自带的 allowed-tools 不采用；脚本只在任务沙箱中运行，读不到平台密钥。自写技能同样适用以上规则。
  - 合规前提：SkillHub 服务协议需用户或法务确认，确认前技能页保持灰显。若合规技能过少，用自写的企业常用技能打底（如会议纪要、合同初审、周报汇总、数据表分析）。

## 10. 对话与产物体验标准（P0，2026-09-26 用户要求达到商业产品水准）

验收以 Sentinel 在群里定的 10 条为准（对话流 1–5、产物面板 6–7、安全 8、性能 9、许可 10），另加以下 4 条：

- 产物预览在 Markdown、代码、表格、图片之外，P0 还要支持 PDF、docx、xlsx 和 HTML（HTML 只在沙箱 iframe 中渲染）；pptx 放 P1，在那之前提供下载和首页缩略图。
- 右侧增加「文件」标签页，显示任务工作空间的文件树；正在写入的文件标「生成中」，写完自动刷新。
- 断网后自动重连，从最后收到的事件接着收，不重复、不丢。
- 工具调用行用业务语言描述动作（如「读取 合同.docx」），完整参数放在展开详情里。

预览安全（纳入第 8 条验收）：
- HTML 预览走 `srcdoc`：前端经鉴权接口取到内容，放进只开 `allow-scripts` 的沙箱 iframe，开头注入 meta CSP（契约 §16，S-AR-8）。
- docx 转出的 HTML 先过 DOMPurify，再放进上述沙箱 iframe。
- PDF 用最新版 pdf.js，并设 `isEvalSupported: false`。
- xlsx 不用 npm 上停更的 `xlsx@0.18.5`，在 Web Worker 里解析，并设文件大小上限。

依赖：断网续传要求 orbit-control 的 `/events` 支持 `Last-Event-ID`；不支持的话在 control 单独补一个小 PR。

右侧产物与文件由 P1 提前到 P0，依赖契约 C30（产物事件与读取接口）。参考实现与许可规则见 `orbit-frontend-borrow-report-v2.md` 第 7 节和 Celestial 的许可证结论。

## 11. 登录鉴权与多租户排期（2026-09-26 产品决定）

- **P0 做登录鉴权和任务归属**：用户必须登录才能使用；每个任务记录创建人，P0 只有创建人能看和操作自己的任务。登录走企业 OIDC 单点登录，开发环境保留本地账号。
- **P0 数据模型带租户**：所有数据带 `tenantId`，P0 每套部署只有一个默认租户，以后开多租户不用迁移数据。跨租户 404 测试用预置的两个租户跑。
- **P1 再做**：任务成员（同事查看同一任务）、项目成员与权限、多租户开通与管理后台、服务账号。
- 排期：鉴权排在 A1 之后，与 A2 并行；产物读取接口排在鉴权之后。对应 P0 成功标准第 6 条。
